  Auth scheme: JWT Bearer tokens
  All protected endpoints require header:
    Authorization: Bearer <access_token>

  Token lifetime: ~60 minutes (access), 7 days (refresh)

  ── Login ──────────────────────────────────────────────────────────────────
  POST /api/v1/auth/login
  Content-Type: application/json
  Body: { "email": "...", "password": "..." }
  Response: {
    "access_token": "eyJ...",
    "refresh_token": "eyJ...",
    "token_type": "bearer",
    "user": { "id": "uuid", "email": "...", "role": "...", ... }
  }

  ── Register ───────────────────────────────────────────────────────────────
  POST /api/v1/auth/register
  Body: {
    "email": "string",
    "password": "string",
    "full_name": "string",
    "role": "child" | "adult" | "moderator" | "authority" | "admin",
    "phone": "string (optional)",
    "language_preference": "en" | "hi" (optional)
  }

  ── Refresh Token ──────────────────────────────────────────────────────────
  POST /api/v1/auth/refresh
  Body: { "refresh_token": "eyJ..." }

  ── Logout ─────────────────────────────────────────────────────────────────
  POST /api/v1/auth/logout
  Headers: Authorization: Bearer <access_token>
  Body: { "refresh_token": "eyJ..." }

  ── Get Current User ───────────────────────────────────────────────────────
  GET /api/v1/auth/me
  Headers: Authorization: Bearer <access_token>
  Response: { "id", "email", "full_name", "role", "phone", ... }

5.2  CASES   /api/v1/cases/
──────────────────────────────────────────────────────────────────────────────
  The central entity of the platform. Every SOS, report, and incident attaches
  to a child's active Case. Cases flow through a human-gated state machine.

  GET    /cases/                  List cases (filter by status, priority, child_id)
    Query params: status, priority, child_id, moderator_id, limit, offset

  POST   /cases/                  Create new case
    Roles: moderator, admin, authority
    Body: { "child_id": uuid, "title": str, "description": str,
            "priority": "low"|"medium"|"high"|"critical", "risk_level": str }

  GET    /cases/{id}              Get case detail (with incidents, notes, moderator)

  PUT    /cases/{id}              Update case fields
    Roles: moderator, admin, authority

  POST   /cases/{id}/notes        Add moderator note to a case
    Roles: moderator, admin
    Body: { "note_type": "observation"|"action"|"escalation", "content": str }

  GET    /cases/{id}/notes        Get all notes on a case

  POST   /cases/{id}/escalate     Escalate a case
    Roles: moderator, admin
    Body: { "reason": str, "target_authority": str }

  POST   /cases/{id}/transition   Transition case status (HUMAN-GATED GATE)
    Roles: moderator, admin, authority
    Body: {
      "to_status": "OPEN"|"ASSIGNED"|"MODERATOR_REVIEW"|"ESCALATED"|
                   "AUTHORITY_NOTIFIED"|"CWC_REFERRED"|"CLOSED"|"DISMISSED",
      "reason": str,
      "statutory_reference": str (optional, e.g. "POCSO Act 2012 Sec 11"),
      "dismissal_category": str (optional, required when dismissing)
    }
    NOTE: All state transitions require a moderator human decision.
    The backend enforces this — no auto-transitions without actor_id.

  POST   /cases/check-sla         Trigger SLA enforcement sweep
    Roles: moderator, admin, authority
    Checks all active cases for SLA breach and auto-escalates overdue ones.

  ── Case Status Values ──────────────────────────────────────────────────────
  OPEN → ASSIGNED → MODERATOR_REVIEW → ESCALATED → AUTHORITY_NOTIFIED →
  CWC_REFERRED → CLOSED
                                     ↘ DISMISSED (with mandatory reason)

  ── Case Priority Values ────────────────────────────────────────────────────
  low | medium | high | critical

5.3  SOS EMERGENCY   /api/v1/sos/
──────────────────────────────────────────────────────────────────────────────
  POST   /sos/trigger             Trigger an emergency SOS
    Auth: Optional (can be anonymous)
    Rate Limited: Yes (Redis sliding window, abuse-resistant)
    Body: {
      "latitude": float,
      "longitude": float,
      "accuracy": float (optional),
      "location_address": str (optional),
      "message": str (optional),
      "child_id": uuid (optional),
      "is_silent_duress": bool (default: false),
      "bypass_primary_guardians": bool (default: false)
    }
    NOTE: is_silent_duress=true routes alerts ONLY to vetted alternate trusted
    adults (not household guardians). Used in domestic abuse scenarios.

  PUT    /sos/{id}/resolve        Resolve an active SOS
    Auth: Optional
    Body: { "message": str (optional) }

  GET    /sos/active              Get all active SOS events
    Query: limit (default 50)

  GET    /sos/nearby              Get SOS events near a location
    Query: latitude, longitude, radius_km (default 10.0)

  GET    /sos/{id}                Get specific SOS event detail

6. WEBSOCKET — REAL-TIME EVENTS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Endpoint:  wss://squishier-clunky-neuter.ngrok-free.dev/ws?token=<access_token>

  The JWT access_token is passed as a query parameter for WebSocket auth.

  ── Connection Handshake ────────────────────────────────────────────────────
  On connect, server sends:
  {
    "event": "CONNECTED",
    "user_id": "uuid",
    "role": "moderator",
    "channels": ["cs:emergency", "cs:user:<user_id>"]
  }

  ── Ping / Keepalive ────────────────────────────────────────────────────────
  Send: { "action": "ping" }
  Receive: { "event": "pong" }
  Recommended: send ping every 30 seconds to keep the connection alive.

  ── Event Types the Portal will receive ─────────────────────────────────────
  All events follow this envelope:
  {
    "event": "EVENT_TYPE",
    "channel": "cs:emergency" | "cs:role:moderator" | "cs:user:<id>",
    "data": { ... event-specific payload ... },
    "timestamp": "ISO datetime"
  }

  EVENT_TYPE          | Trigger                        | Payload
  --------------------|--------------------------------|----------------------
  SOS_TRIGGERED       | Child presses SOS button or    | SOS object (see 5.3)
                      | silent duress hardware trigger  |
  SOS_RESOLVED        | SOS is resolved                | SOS object
  CASE_STATUS_CHANGED | Moderator transitions a case   | { case_id, from_status,
                      |                                | to_status, reason,
                      |                                | actor_id }
  CHAT_MESSAGE        | Incoming message from child or | { case_id, protected_case_id,
                      | safety protector               | message: { id, content,
                      |                                | sender_id, sender_role, ... } }
  CONNECTED           | Connection established         | { user_id, role }
  pong                | Response to ping               | (empty)

  ── React Example ───────────────────────────────────────────────────────────
  const token = localStorage.getItem('access_token');
  const ws = new WebSocket(
    `wss://squishier-clunky-neuter.ngrok-free.dev/ws?token=${token}`
  );

  ws.onopen = () => {
    console.log('Connected to Child Safety real-time feed');
    setInterval(() => ws.send(JSON.stringify({ action: 'ping' })), 30000);
  };

  ws.onmessage = (event) => {
    const msg = JSON.parse(event.data);
    if (msg.event === 'SOS_TRIGGERED') {
      // Show emergency alert in dashboard
      showEmergencyBanner(msg.data);
    }
    if (msg.event === 'CASE_STATUS_CHANGED') {
      // Refresh case list or update case card
      refreshCaseList();
    }
  };

  ws.onclose = () => {
    // Reconnect with exponential backoff
  };

7. KEY ARCHITECTURAL RULES FOR THE REACT PORTAL
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  1. HUMAN-IN-THE-LOOP IS MANDATORY
     No case moves from MODERATOR_REVIEW to any downstream status without a
     logged-in moderator explicitly calling POST /cases/{id}/transition.
     The portal MUST show a confirmation dialog before calling this endpoint.
     Never auto-transition cases in the frontend.

  2. SILENT DURESS SOS
     When is_silent_duress=true in a SOS_TRIGGERED WebSocket event:
     - Display with RED CRITICAL alert (different from normal SOS)
     - Label it "SILENT DURESS — Domestic abuse scenario"
     - Do NOT notify household guardians (already handled by backend)
     - Escalate immediately to trusted adults + moderator

  3. SLA AWARENESS
     Call POST /cases/check-sla periodically (e.g. on portal load) to trigger
     SLA enforcement. Cases with:
       SLA Tier | Breach Time
       SOS      | 15 minutes
       CRITICAL | 2 hours
     are auto-reassigned to available moderators by the backend.

  4. EVIDENCE CHAIN OF CUSTODY
     Before displaying evidence to a moderator, call:
       GET /evidence/{id}/verify-custody
     And show the integrity status. If tampered, mark with a warning banner.
     Evidence is linked to Indian law (BSA 2023 Sec 63) for court admissibility.

  5. ANONYMOUS REPORTS ARE RATE-LIMITED
     The backend Redis rate limiter allows 5 reports per IP per 10 minutes.

  // api.js
  import axios from 'axios';

  const api = axios.create({
    baseURL: 'https://squishier-clunky-neuter.ngrok-free.dev',
    headers: {
      'Content-Type': 'application/json',
      'ngrok-skip-browser-warning': '1',   // REQUIRED — prevents ngrok interstitial
    },
  });

  // Auto-attach JWT on every request
  api.interceptors.request.use((config) => {
    const token = localStorage.getItem('access_token');
    if (token) config.headers.Authorization = `Bearer ${token}`;
    return config;
  });

  // Auto-refresh on 401
  api.interceptors.response.use(
    (res) => res,
    async (err) => {
      if (err.response?.status === 401) {
        const refreshToken = localStorage.getItem('refresh_token');
        if (refreshToken) {
          try {
            const res = await axios.post(
              'https://squishier-clunky-neuter.ngrok-free.dev/api/v1/auth/refresh',
              { refresh_token: refreshToken },
              { headers: { 'ngrok-skip-browser-warning': '1' } }
            );
            localStorage.setItem('access_token', res.data.access_token);
            err.config.headers.Authorization = `Bearer ${res.data.access_token}`;
            return api.request(err.config);
          } catch {
            localStorage.clear();
            window.location.href = '/login';
          }
        }
      }
      return Promise.reject(err);
    }
  );

  export default api;
